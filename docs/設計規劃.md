# 設計規劃（開發前撰寫）

> 這是動工前寫的規劃文件，保留作為紀錄。實際做法與結果以 [README](../README.md)、[技術細節](技術細節.md) 與 [評估報告](評估報告.md) 為準（例如 LLM 後來改用本機 Ollama、PDF 改用 PyMuPDF 純文字）。

> 中興大學資管系碩士班畢業門檻的單一查詢窗口。
> 目標：一週內完成一個可運作、可評估的 RAG 系統，累積 LLM / RAG 實作經驗。

---

## 1. 專案定位

**要做的**
- 把散落在校級、系級、各處室的畢業相關規章整理成單一知識庫
- 問「我112入學，外系學分可以抵幾學分」→ 回答 + 引用條文 + 辦理處室 + 需繳文件
- 有一組固定的評估題目，能量化「這次改動有沒有變好」

**不做的（一週內）**
- 模型微調（embedding / LLM 都不碰，效益比不上把資料做好）
- 多使用者系統、登入、資料庫後台
- 畢業門檻以外的主題（補助、宿舍、兵役）— 但 schema 預留欄位

**核心設計難點**

同一條規定會因**入學學年度**而不同。例如外系學分承認上限，107前入學 3 學分、108–110 入學 6 學分、111 後又回 3 學分。若不做學年度過濾，系統會穩定地給錯答案。

→ **學年度與學制是檢索的硬過濾條件，不是回答時的附註。** 整個專案的架構都繞著這點走。

### 4.2 蒐集原則

- **HTML 優先**於 PDF，結構乾淨、好解析
- 必修科目表這類**表格**不要丟 parser，手動轉成 CSV 另存（見 4.4）
- 舊學年度版本若系網只掛最新版 → 查 Wayback Machine，或直接寄信問系辦
- 每份文件記進 `sources.csv`：`url, title, office, fetched_at, sha256`

### 4.3 Chunk Schema（`src/schema.py`）

```python
class Chunk(BaseModel):
    chunk_id: str
    doc_id: str
    title: str                      # "資管系碩士班研究生須知"
    text: str                       # 條文原文
    text_with_header: str           # 加了上下文前綴的版本（實際拿去 embed）

    # --- 過濾用，最重要 ---
    level: Literal["校級", "院級", "系級", "作業層", "非正式"]
    applicable_year_from: int | None    # 適用入學學年度起，None = 不分
    applicable_year_to: int | None      # None = 現行有效
    applicable_program: list[str]       # ["碩士班"] / ["碩專班"] / ["全部"]
    applicable_group: list[str]         # ["全部"] or ["甲組","乙組"]

    # --- 回答用 ---
    responsible_office: str         # "資管系系辦"
    topic: list[str]                # ["學分","抵免"]
    article_no: str | None          # "第三條" / "四、"
    forms: list[str]                # ["選修外系課程申請書"]

    # --- 溯源用 ---
    source_url: str
    revision_date: str | None
    is_informal: bool = False
```

`applicable_year_from/to` 與 `applicable_program` 填錯 = 系統給錯答案。這兩個欄位人工覆核，不要全信自動抽取。

## 5. 處理管線

### 5.1 Chunking（`src/chunker.py`）

**不要用固定長度切塊。** 法規用條文切：

- 切分錨點：`^第[一二三四五六七八九十百]+條`、`^[一二三四五六七八九十]+、`、`^\([一二三四五六七八九十]+\)`、Markdown heading
- 單條超過 800 字才二次切，子塊前綴補上條次
- 每個 chunk 的 `text_with_header` 格式：

```
【文件】資管系碩士班研究生須知（114.02.19 修訂）
【適用】111 學年度(含)後入學之碩士班
【主責】資管系系辦
【條次】三、抵免學分規定
---
<原文>
```

把適用範圍寫進 embed 的文字裡，使用者問「112入學…」時會直接命中，不只靠 metadata filter。

### 5.2 Indexing（`src/index.py`）

- ChromaDB collection，metadata 全部存進去（list 型欄位轉成逗號字串，Chroma 不吃 list）
- 同時建 BM25 index，jieba 自訂詞典加入：
  `學位考試 / 抵免學分 / 原創性比對 / 指導教授同意書 / 畢業學分 / 學術倫理 / 碩士在職專班 / 提前畢業 / 選修外系課程申請書`
- BM25 index 用 pickle 存到 `data/bm25.pkl`

### 5.3 檢索（`src/retrieve.py`）

```
query
  → slots.extract()            # 抽 學年度 / 學制 / 組別
  → build_filter()             # 組 Chroma where 條件
  → dense search (top 20)  ─┐
  → bm25 search  (top 20)  ─┴→ RRF 融合 → top 10
  → rerank (可選)             → top 5
```

**Metadata filter 邏輯**
```python
where = {
    "$and": [
        {"$or": [{"applicable_year_from": {"$lte": year}},
                 {"applicable_year_from": -1}]},     # -1 代表不分學年度
        {"$or": [{"applicable_year_to": {"$gte": year}},
                 {"applicable_year_to": -1}]},
        {"program_str": {"$in": [program, "全部"]}},
    ]
}
```

**槽位缺失處理**：若問題涉及會因學年度而異的主題（學分、抵免、必修、提前畢業）但使用者沒給學年度 → **反問，不要猜**。這是這個系統最重要的行為。

### 5.4 生成（`src/generate.py`）

System prompt 要包含：

```
你是中興大學資管系碩士班的行政法規查詢助理。

規則：
1. 只能依據提供的 <context> 回答。context 沒有的資訊，明確說「現有規章未涵蓋此項，
   建議洽詢 <最相關處室>」，絕不自行推測。
2. 每項事實後標註來源編號 [1][2]，回答末尾列出來源文件名稱與連結。
3. 若 context 中的規定標示了適用學年度，且與使用者的學年度不符，不得使用該條。
4. 回答格式固定：
   ## 結論
   ## 依據
   ## 需繳交文件
   ## 辦理處室與期限
5. 絕不捏造表單名稱、表單代碼、期限或處室名稱。
6. 若規定因入學學年度而異，主動說明。

最後固定附上：本回答僅供參考，請以各處室公告與承辦人說明為準。
```

## 6. 評估集

### 6.1 規模與來源（目標 50 題，一天內做完）

| 來源 | 題數 |
|---|---|
| 從法規條文反向出題（LLM 生成後人工篩） | 20 |
| 自己與同學實際遇過的問題 | 15 |
| 對抗性題目 | 10 |
| 不可答題目 | 5 |

### 6.2 題型標籤

- `T1` 事實查詢 — 最低畢業學分是多少
- `T2` 條件判斷 — 我112入學乙組，外系抵免上限
- `T3` 流程導引 — 下學期要口試，現在起要做什麼
- `T4` 多跳 — 需串接系規 + 校級學則
- `T5` 窗口定位 — 這份表單交去哪
- `T6` 不可答 — 規章未涵蓋，正解是拒答 + 轉介

### 6.3 對抗性題目（必做）

- **學年度陷阱**：「外系學分可以抵幾學分？」（不給學年度 → 正解是反問）
- **學制混淆**：「我碩專班的，提前畢業條件？」（不能套用碩士班答案）
- **錯誤前提**：「口試完再做 Turnitin 就好對吧？」（要糾正前提）
- **不存在的表單**：「G9-3 表要去哪交？」（正解是說沒有這份表單）

### 6.4 題目格式（`eval/questions.jsonl`）

```json
{
  "qid": "Q012",
  "question": "我112學年度入學碩士班，想修管理學院的課，最多可以採計幾學分？",
  "type": "T2",
  "slots": {"year": 112, "program": "碩士班"},
  "gold_chunk_ids": ["mis-rules-2023#art3"],
  "gold_answer_points": ["上限X學分", "需填選修外系課程申請書", "需指導教授簽章", "送系辦存查"],
  "gold_office": "資管系系辦",
  "answerable": true
}
```

`gold_answer_points` 用**要點列表**而非完整句子，評估時好對；完整答案對不起來也難標。

### 6.5 指標（`src/evaluate.py`）

| 指標 | 怎麼算 | 目標 |
|---|---|---|
| Recall@5 | gold_chunk_ids 有沒有在 top5 | > 0.85 |
| 要點涵蓋率 | 命中幾個 gold_answer_points（人工或 LLM-as-judge） | > 0.8 |
| 窗口正確率 | 回答的處室 == gold_office | > 0.9 |
| 適當拒答率 | T6 題目正確拒答比例 | 1.0 |
| 幻覺數 | 捏造表單/期限/處室的題數 | 0 |

每次改動後跑 `python -m src.evaluate`，把結果存到 `eval/results/{timestamp}.json`，比較前後。

## 9. 踩雷預告

1. **ChromaDB 不支援 list 型 metadata** — 轉成 `"碩士班,全部"` 這種逗號字串，filter 用 `$in` 或字串包含
2. **`None` 不能存進 Chroma metadata** — 用 `-1` 或 `""` 代替
3. **PDF 表格會被解析成一坨亂碼** — 必修科目表手動轉 CSV，別硬解
4. **中文 BM25 不斷詞等於沒用** — jieba 自訂詞典一定要加
5. **LLM 會把「建議洽詢系辦」講得很像確定答案** — prompt 要求不確定時用明確的否定句式
6. **評估題目自己出會太簡單** — 刻意放進那些你自己當初搞不清楚的問題
7. **bge-m3 第一次載模型要下載 2GB 左右** — Day 1 就先跑一次把模型抓下來
